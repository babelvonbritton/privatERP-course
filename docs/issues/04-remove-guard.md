# Issue 4: The Guard validation class is dead code

- Category: `enhancement`
- State: `ready-for-agent`
- Severity: should fix (Ponytail audit v1.0.6, finding 4)

> *This was generated by AI during triage.*

## Problem

The Guard class exports text, oneOf, and dateOrNull methods. Validation moved
to zod schemas, and a search over source, tests, scripts, and config finds
zero callers of any Guard method. Only ValidationError, defined in the same
file, is still used (by six files). The security doc still credits Guard with
enforcing input limits, which is no longer true.

## Fix

Delete the Guard class, its TextRules interface, and its now-unused imports.
Keep ValidationError and its ValidationKind type in the file. Fix the security
doc credit as part of issue 5. No behaviour changes.

## Acceptance

- No reference to Guard remains anywhere except the history.
- ValidationError and ValidationKind still exist and are imported the same way.
- All existing tests still pass.
